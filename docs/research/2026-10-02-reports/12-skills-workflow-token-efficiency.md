## 1) Executive summary

1. **Agent Skills (`SKILL.md`) is the lingua franca.** The open spec (agentskills.io, originally Anthropic, Apache-2.0 code / CC-BY-4.0 docs, 25.8k-star spec repo) is implemented by 40+ clients including Claude Code, Codex/ChatGPT, Gemini CLI, Cursor, OpenCode, GitHub Copilot/VS Code, Goose, Amp, Kiro, Factory, Roo, Junie and Ona. The portable subset is just `name`, `description`, `license`, `compatibility`, `metadata`, `allowed-tools`; everything else (Claude Code's `model`, `effort`, `context: fork`, `hooks`, `paths`…) is harness-specific. ByteBureau should author/sync skills to the standard subset and let per-harness adapters add extensions. The de-facto cross-tool directory is **`.agents/skills/`** (Codex, OpenCode, Gemini CLI, Cursor, Copilot all read it); Claude Code reads `.claude/skills/` (and Cursor/OpenCode/Copilot also read `.claude/skills/`).

2. **Sync mechanism: Vercel `skills` CLI + ByteBureau-owned pinned manifest + scanning.** `npx skills add <owner/repo> --skill <name> -a <agent> -y` installs into every supported agent's directory (78 agents, symlink by default, `--copy` to copy, `@ref` to pin). For Claude Code specifically, a ByteBureau-owned plugin marketplace (`marketplace.json` with `github` sources pinned by 40-char `sha`, archive `sha256`) gives reproducible installs; third-party marketplaces do **not** auto-update unless the user enables it, so ByteBureau's own updater controls bumps. Never auto-install from open registries: Snyk's ToxicSkills audit (2026-02-05) found 13.4% of 3,984 skills on ClawHub/skills.sh had critical issues and 76 confirmed malicious payloads (91% using prompt injection). Scan on every update (`uvx mcp-scan@latest --skills`, `claude plugin validate`, custom heuristics), pin, diff, and ask the owner only when the diff is non-trivial.

3. **Curated default set (ranked):** obra/superpowers core (15 skills, MIT, v6.4.2 of 2026-09-25, 293,954 stars) as the workflow backbone; Anthropic's official plugins `pr-review-toolkit`, `code-review`, `security-guidance` (official marketplace, auto-updated by Anthropic); `vercel-labs/agent-skills` React/web-design skills (MIT); cherry-picked skills from affaan-m/ECC (MIT, v2.2.3 of 2026-10-01, 293 skills — too large to install whole); optionally `trailofbits/skills` for the Security Reviewer (CC-BY-SA-4.0: share-alike, keep out of ByteBureau's own distribution). Rejected as defaults: BMAD-METHOD, SuperClaude, claude-flow/Ruflo, davila7/claude-code-templates, SkillsMP/ClawHub as sources.

4. **Token efficiency is mostly about cache hygiene and context isolation, not clever prompting.** Facts that drive the ruleset: Claude Code caches automatically, subscription sessions get a 1-hour TTL on the main conversation (5 min for subagents unless `subagentPromptCacheTtl: 1h`), and the invalidators are model switch, effort change (except Opus 5.5/Sonnet 5.5/Fable 5.1), fast mode, MCP server changes (unless tool search), compaction, image accumulation and upgrades. Subagents return only summaries; agent teams cost ~7x; dynamic workflows keep intermediate results out of context entirely. Effort is the primary cost lever on Opus 5.5 (default `medium`) and Sonnet 5.5 (Claude Code default `medium`); Haiku 4.5 (200K context, $1/$5) is the right model for triage/summaries/scribe work; Ollama exposes an Anthropic-compatible endpoint for truly cheap jobs (commit messages, PR descriptions). Programmatic tool calling (-38% input tokens on a 75-tool benchmark) and tool search (72K→8.7K tokens, 85%) matter only for API-level custom agents; Claude Code already defers MCP tools by default.

5. **Multi-agent design: one orchestrator per work item with dynamic subagents, driven by a deterministic state machine — not a peer swarm.** Anthropic's own evidence: multi-agent research beat single Opus by 90.2% but used ~15x tokens, token usage explains 80% of variance, and "most coding tasks involve fewer truly parallelizable tasks than research". Claude Code's docs say agent teams use ~7x tokens and are experimental/not available in `-p`. Codex and OpenCode offer equivalent subagent primitives (per-agent model + reasoning effort), so the roster is portable. MetaGPT/ChatDev validate role specialization + phase artifacts + reviewer/tester loops, but their outputs were toy apps; ByteBureau grounds every phase in real repo/tests/CI.

6. **Human-in-the-loop primitives exist in every harness:** Claude Code `AskUserQuestion` (1–4 questions, 2–4 options, header ≤12 chars, "Other" free text, `askUserQuestionTimeout` 60s/5m/10m auto-closes unanswered questions; not available inside subagents), SDK `canUseTool` (allow/deny/`updatedInput`/`updatedPermissions`, option previews), PreToolUse `defer` (process exits, resume with `claude --continue --decision allow`), `PermissionRequest`/`Notification` hooks for phone/Slack notifications; Codex app-server `item/*/requestApproval` + `turn/interrupt`; OpenCode `question`/`ask` permissions; ACP `session/request_permission` (`allow_once|allow_always|reject_once|reject_always`). ByteBureau's "recommended option" rule should require evidence citations (file:line, test output, doc URL) in the question payload and auto-proceed with the recommended option after a configurable timeout when the human is away.

7. **Dev-workflow automation has strong reference implementations:** GitHub Copilot coding agent (assign issue → draft PR, `@copilot` review comments, cannot approve/merge), `anthropics/claude-code-action@v1` (interactive `@claude` + automation mode; **subscription OAuth token officially supported** via `claude setup-token`), Claude Code cloud "auto-fix pull requests" (reacts to CI failures and review comments, asks when ambiguous), routines (GitHub `pull_request`/`release` triggers), Linear Agents API (session/activity model, acknowledge within 10 s), Codex-in-Linear, Cursor cloud agents. Jira specifics: uppercase issue key in branch/commit/PR title for auto-linking; the official Atlassian MCP accepts **markdown** comments (`addOrEditJiraIssueComment`) and `transitionJiraIssue` by `transitionId`/`transitionName`; comments passed in a transition's `update` may be silently dropped (use a separate comment call).

8. **Critical legal/ToS finding (risk register #1).** Anthropic's Claude Code legal page: OAuth login is "intended exclusively for purchasers of … subscription plans and is designed to support ordinary use of Claude Code"; "Advertised usage limits for Pro and Max plans assume ordinary, individual usage of Claude Code and the Agent SDK"; third-party developers "may not … route requests through Free, Pro, or Max plan credentials on behalf of their users" and may not collect/store/intermediate claude.ai credentials or session tokens; **but** an end user may sign in to the **unmodified Claude Code binary** with their own subscription even when a platform hosts it. The Agent SDK overview says Anthropic "does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK". Consumer terms also forbid account sharing and "automated or non-human means" except via API key or explicit permission. Implication: ByteBureau must orchestrate the user's own unmodified `claude` CLI (headless `-p` or interactive), never embed OAuth-authenticated SDK sessions, never store tokens, and never rotate multiple accounts. (Also: `claude --bare` does not use the subscription login — it needs an API key.)

### 2.1 Agent Skills open standard

**Spec (agentskills.io/specification, fetched 2026-10-02):**
- Directory: `skill-name/SKILL.md` (required) + optional `scripts/`, `references/`, `assets/`.
- Frontmatter: `name` (1–64 chars, `^[a-z0-9]+(-[a-z0-9]+)*$`, must equal directory name), `description` (1–1024 chars, what + when), `license`, `compatibility` (≤500 chars), `metadata` (string→string map), `allowed-tools` (space-separated, experimental).
- Progressive disclosure: metadata ~100 tokens at startup; body (<5000 tokens recommended, <500 lines) on activation; resources on demand; references one level deep.
- Validator: `skills-ref validate ./my-skill` (github.com/agentskills/agentskills/tree/main/skills-ref). Spec repo: 25.8k stars, Apache-2.0 (code) / CC-BY-4.0 (docs), originally Anthropic, "open to contributions"; no formal foundation governance stated on the page (AGENTS.md, by contrast, is stewarded by the Agentic AI Foundation under the Linux Foundation).

**Client support (agentskills.io home, client carousel, 2026-10-02):** Claude Code, Claude (claude.ai/API), ChatGPT & Codex, Gemini CLI, Cursor, Amp, OpenCode, OpenHands, GitHub Copilot, VS Code, Goose, Letta, Mux (Coder), Emdash, Superconductor, Factory, Kiro, Roo Code, Junie, Pulumi Neo, Snowflake Cortex Code, Databricks Genie Code, Spring AI, Laravel Boost, Mistral Vibe, Hermes Agent, OpenClaw, nanobot, fast-agent, pi, Tabnine, Qodo, TRAE, Workshop, Deep Code, VT Code, ZeroClaw, Firebender, Autohand, Agentman, Vita, bub, Command Code, Google AI Edge Gallery.

### 2.2 Skills CLI, marketplaces, sync mechanics

**Vercel `skills` CLI (github.com/vercel-labs/skills; skills.sh):** 32,939 stars, MIT, created 2026-01-14, last push 2026-09-30. Commands: `add`, `use` (run without installing), `list`, `find`, `update`, `remove`, `init`. Flags: `-a/--agent`, `-g/--global`, `-s/--skill`, `--copy` (copy instead of symlink), `-y/--yes`, `--list`, `--all`. 78 supported agents with per-agent directories (Claude Code, OpenCode, Cursor, Codex, Cline, Copilot, Continue, OpenHands, Devin, Windsurf, Roo…). Version pinning through git refs in the source spec (`owner/repo@ref`); the README does not document a lockfile (**unverified**: whether a lockfile exists in newer versions). Private repos via git credentials/`GITHUB_TOKEN`. Download limits 10 MiB/file, 25 MiB extracted, 1000 files. Telemetry (opt-out `DISABLE_TELEMETRY`/`DO_NOT_TRACK`). skills.sh lists ~1.5M skills ranked by 8-week installs (top: `vercel-labs/find-skills`, 3.7M installs) and has a "Security audits" section (details page returned 404 — **unverified**).

**Claude Code plugin marketplaces (code.claude.com/docs/en/plugins/*, fetched 2026-10-02):**
- `marketplace.json` requires `name`, `owner`, `plugins[]`; plugin sources: relative path, `github` (`repo`, `ref`, `sha`), `url` (git), `git-subdir`, `npm` (no install scripts run), `archive` (HTTPS zip + `sha256` pin → refuses mismatched download), `command`. `sha` is a full 40-char lowercase commit SHA and wins over `ref`.
- Versioning: computed from `plugin.json` `version` → entry `version` → commit SHA (12 chars) / archive digest; users receive a new copy only when the computed version changes. `renames` map and `forceRemoveDeletedPlugins` for safe removals; release channels = two marketplaces pointing at different refs.
- **Auto-update is off by default for third-party marketplaces**; on by default only for Anthropic's official ones and claude.ai-hosted ones. When on, Claude Code waits a random delay (up to 10 min) after the first message of an interactive session, refreshes marketplaces, updates plugins on disk, and prompts `/reload-plugins`. `DISABLE_AUTOUPDATER=1` disables the pass (unless `FORCE_AUTOUPDATE_PLUGINS=1`).
- Tooling: `claude plugin validate`, `claude plugin details <name>` (component inventory + projected always-on token cost per component), `claude plugin eval` (eval suites with regex/tool-used/LLM-rubric graders, 3 runs/case, no-plugin baseline, CI gating), `/skill-doctor` (skills never invoked), `/doctor` (unused plugins), `/usage` attribution by skill/subagent/plugin/MCP.
- Security page: plugins "can execute arbitrary code on your machine with your user privileges"; hooks/MCP servers/mods run **outside the sandbox**; review `hooks/hooks.json`, `.mcp.json`, `bin/`; official/community marketplace names are reserved and only accepted from `github.com/anthropics/`; `claude-community` pins nearly every entry to a commit SHA; managed settings can `strictKnownMarketplaces`/`blockedMarketplaces`. Subagent final reports are scanned for instruction-shaped patterns (control tags neutralized, `[harness: …]` marker prepended).
- Project distribution: `.claude/skills/` in the repo loads only after the workspace trust dialog; Claude Code does not scan a project's `.claude/plugins/`.

**Other registries:**
- SkillsMP (skillsmp.com): "3,000,000+ open-source skills", crawled from GitHub, free REST/MCP API; **no curation or security scanning described**; operator not identified.
- ClawHub (clawhub.ai): OpenClaw's registry (~30 skills, 12 plugins), `clawhub` CLI, "signed manifests, moderated releases" claimed; was one of the two sources in Snyk's ToxicSkills audit.
- VoltAgent/awesome-agent-skills: 35.1k stars, "1,497+ skills", lists official vendor skills (Anthropic, Google, Microsoft (133), Cloudflare, Vercel, Netlify, Trail of Bits, Sentry, Stripe, HashiCorp, OpenAI…), curation claim "hand-picked, not AI-slop generated".
- hesreallyhim/awesome-claude-code: 54,906 stars, license NOASSERTION, generated README from `config.yaml`; discovery only, not installable.

**Supply-chain evidence:** Snyk "ToxicSkills" (2026-02-05): 3,984 skills from ClawHub + skills.sh; 13.4% (534) with critical issues; 36.82% with at least one flaw; 76 confirmed malicious; 8 still public at publication; vectors = prompt injection via base64/Unicode smuggling (91% of malicious), credential exfiltration in install instructions, external password-protected archives with backdoors; mitigation `uvx mcp-scan@latest --skills`, rotate credentials, review agent memory files. Claude Code docs independently warn that skills/commands/agents "enter Claude's context as instructions". Gemini CLI mitigates with a per-activation consent prompt.

### 2.4 Token efficiency (2026)

**Prompt caching — API (platform.claude.com/docs/en/build-with-claude/prompt-caching):** two modes — automatic (top-level `cache_control: {type: "ephemeral"}`, breakpoint moves forward automatically) and explicit breakpoints (max 4, 20-block lookback). TTL 5 min default (refresh free), 1 h at 2x base input price; cache writes 1.25x (5m) / 2x (1h); cache reads 0.1x (Opus 5.5 0.05x; Fable 5.1/Mythos 5.1 0.025x). Minimum cacheable prefix: 512 tokens on Fable 5.1/Opus 5.5/Opus 5/Sonnet 5.5/Fable 5; 1,024 on Sonnet 5/Opus 4.8/Sonnet 4.6; 2,048 Opus 4.7; **4,096 on Haiku 4.5** and Opus 4.6. Hierarchy tools → system → messages; tool-definition changes invalidate everything; thinking/effort changes are model-dependent. Cache entry is usable only after the first response begins (parallel fan-outs must wait). Per-message effort change (beta `mid-conversation-output-config-2026-07-01`, Opus 5.5/Opus 5/Sonnet 5.5/Fable 5.1) keeps the cache; top-level effort change invalidates it. Mid-conversation `role: system` messages (no beta; Opus 5/5.5, Fable, Sonnet 5.5) are the cache-safe operator channel (claude-api skill reference, cached 2026-09-25).

**Prompt caching — Claude Code (code.claude.com/docs/en/prompt-caching):** automatic; request layers = system prompt (tools) → project context (CLAUDE.md, auto memory, unscoped rules) → conversation. - Review loop: prefer **webhooks** (`pull_request_review` submitted with state approved/changes_requested/commented, `pull_request_review_comment` created, `pull_request_review_thread` resolved/unresolved, `check_suite`/`check_run` completed, `issue_comment` created, `pull_request` synchronize/closed) with a **polling fallback** (`gh pr view --json reviews,reviewDecision,statusCheckRollup,comments`) for machines without inbound HTTP; after addressing comments: push, reply on each thread, re-request review (`POST /repos/{o}/{r}/pulls/{n}/requested_reviewers`; "creating content too quickly… may result in secondary rate limiting"). Claude Code auto-fix behaviour (fix clear ones, ask on ambiguous/architectural) is the right policy.
- Slack etiquette: one thread per PR (`thread_ts`), mention reviewer `<@U…>`, `chat.update` the root message with status, `reply_broadcast` only for final "merged"; interactive Approve/Changes buttons need an Interactivity Request URL or Socket Mode (`block_actions`, 3-second ack, `response_url` up to 5 times/30 min); `chat.postMessage` ~1 msg/s/channel.
- Merge: `gh pr merge --squash --auto --delete-branch` (auto-merge waits for required reviews/checks; repo must enable auto-merge; `delete_branch_on_merge` repo setting; `--admin` to bypass — never by default); squash commit subject = conventional commit title, body = PR summary.
- Edge cases: "no ticket" → skip Jira steps, derive branch/PR from prompt, still produce tester notes in the PR; "no review" → self-review (Reviewer employee) + required CI, then auto-merge if policy allows; "dry-run" → every external side effect (Jira transition/comment, Slack post, push, PR create, merge) goes through a side-effect gateway with `dryRun` that records intended calls instead of executing (GitHub Actions/claude-code-action pattern of listing allowed tools maps cleanly onto this).

## 3) Ranked recommendations + risks

### 3.1 Skills strategy (collections, sync, integrity)

1. **Canonical layout:** author ByteBureau's own skills to the standard subset; store project skills in `.agents/skills/` and symlink `.claude/skills/` → `.agents/skills/` (Claude Code doesn't read `.agents/skills/`; OpenCode/Cursor/Copilot read both). Per-harness extensions live in an optional sidecar (e.g. `SKILL.claude.yaml` merged at install time by ByteBureau's adapter), never in the shared frontmatter (claude.ai/Skills API rejects unknown keys).
2. **Sync engine:** wrap the Vercel `skills` CLI (`npx skills add <repo> --skill <name> -a claude-code -a codex -a opencode -y`, `--copy` inside containers; symlinks at home) behind a ByteBureau manifest `bytebureau.skills.json` listing `{source, skill, ref, commitSha, treeSha256, license, scannedAt, evalScore}`. Updates run on a schedule (daily) in **dry-run**: fetch, diff, scan, run the skill's eval suite if present, then open an asking-dialog ("Update superpowers 6.4.2→6.5.0? Recommended: yes — diff 42 lines, scan clean, evals 9/9") with auto-apply after N hours if the diff touches only Markdown and the scan is clean. For Claude Code, publish the pinned set as a ByteBureau marketplace (`github` sources with `sha`, `archive` with `sha256`) and keep the marketplace's auto-update **off** so Claude Code never updates behind ByteBureau's back.
3. **Default roster of skills (v1):** superpowers core (all 15; the `using-superpowers` bootstrap is reproduced by ByteBureau's own session-start injection for non-Claude harnesses, per `porting-to-a-new-harness.md`); official `pr-review-toolkit`, `code-review`, `security-guidance`; `vercel-labs/agent-skills` (`react-best-practices`, `web-design-guidelines`) only for repos that use React/Next; ECC cherry-picks after per-skill review (candidates `context-budget`, `coding-standards`, `api-design`, `e2e-testing`, `database-migrations`, `deployment-patterns`); `anthropics/skills` `skill-creator`; optional `trailofbits/skills` for security tasks (installed from upstream only; CC-BY-SA).
4. **Integrity gates (every install/update):** pinned SHA; `claude plugin validate` + `skills-ref validate`; `uvx mcp-scan@latest --skills`; ByteBureau heuristics: base64/Unicode-smuggling in Markdown, `curl|sh`, URLs to archives, env-var harvesting in `scripts/`, hooks/`.mcp.json`/`bin/` present → require manual review; run `scripts/` only inside the task container; `disableSkillShellExecution: true` for any skill not on the trusted list; keep always-on listing cost visible (`claude plugin details`, `/skill-doctor`); never source from SkillsMP/ClawHub/skills.sh leaderboard automatically.
5. **Measure before promoting:** maintain `evals/` for ByteBureau's own skills and run `claude plugin eval` (3 runs/case, no-plugin baseline) in CI; trim descriptions that never trigger; keep total always-on cost ≲1% of context.

**Risks:** cross-harness feature gaps (hooks/`context: fork` exist only in Claude Code) → design skills to degrade gracefully; license mixing (CC-BY-SA, NOASSERTION, source-available) → license field required in manifest; symlink/trust rules (Claude Code refuses symlinks outside the plugin/marketplace; project `.claude/skills` loads only after workspace trust).

### 3.2 Token-efficiency ruleset for ByteBureau (ordered by impact)

1. **Stable prefixes per employee.** Each employee has a frozen system prompt + role CLAUDE.md (<200 lines, no timestamps/IDs); all volatile data (ticket text, diffs, review comments) arrives as user messages. Verify with `prompt_cache.hit_ratio` ≥0.85 per session; alert on `/usage` behavior flags (cache misses ≥10%).
2. **Pick model + effort at spawn; never change mid-session** (cache is model/effort-scoped except Opus 5.5/Sonnet 5.5/Fable 5.1 effort changes). No `opusplan`, no fast mode (credits-only anyway).
3. **One work item = one session; `/clear` between items; `/compact <focus>` only at phase gates** (after plan approval, after PR opened). Set `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` ≈70 for long Developer sessions on 1M models; add a `# Compact instructions` section to each role's CLAUDE.md (keep plan, decisions, failing tests, open review threads).
4. **Isolate noise in subagents:** tests, logs, doc fetches, exploration → `Explore`/custom read-only subagents returning ≤300-token summaries; `omitClaudeMd: true` for utility subagents; `maxTurns` on every subagent; depth ≤2, ≤5 concurrent per work item; forks only when the parent context is actually needed.
5. **Effort by role:** low for Scribe/Communicator/Dispatcher, medium for Developer/QA (default), high for Architect/Reviewer, xhigh only on explicit escalation (ultracode never by default). Prefer "newest model at lower effort" over multi-model cascades inside one session.
6. **Model by role:** Haiku 4.5 for triage/summaries/formatting (note 4,096-token minimum cacheable prefix and 200K window), Sonnet 5.5 for well-specified implementation/QA, Opus 5.5 for architecture/review/ambiguous implementation; Ollama (local) for commit messages, PR-description drafts, Jira/Slack formatting — validated by a cheap Haiku check or template.
7. **Tool hygiene:** `gh`/`jira` CLIs over MCP; MCP tool search on (default); disable unused servers; `BASH_MAX_OUTPUT_LENGTH` ≤30K; PreToolUse hooks that rewrite test/lint commands to failure-only output; LSP/code-intelligence plugins for TS.
8. **Skill hygiene:** always-on listing ≲1% of context; `disable-model-invocation: true` for side-effect skills (commit, push, slack, jira); prefer path-scoped rules over giant CLAUDE.md; `/doctor prompt-audit` monthly.
9. **Budgets & stop rules:** per work item `maxTurns`/turn caps in `-p`, SDK `maxBudgetUsd` when on API keys; Ralph-style stop after 2 consecutive no-progress rounds; subagent spawn depth/concurrency caps; per-phase token targets recorded from `--output-format json` (`total_cost_usd`, `modelUsage`, cache tokens).
10. **Pacing on subscriptions:** read `rate_limits.five_hour.used_percentage`/`seven_day` (status-line JSON; `/usage`); pause the queue at 80% of the 5-hour window and keep a weekly reserve (e.g. stop non-urgent work at 85% of 7-day); respect per-model-family limits by routing to the other family when one is exhausted; enable `autoContinueAtUsageLimit` for interrupted turns; keep the 1-h TTL warm by not idling >60 min mid-task (resume from summary otherwise).
11. **Measure tokens/task:** persist per work item and per phase: input/output/cache-read/cache-write tokens, model, effort, turns, wall time, outcome; weekly report; use `/insights`-style analysis to find waste (long context, cache misses, scheduled loops).
12. **AGENTS.md/CLAUDE.md hygiene:** keep facts not derivable from code; `/doctor` trims; `claude-md-and-agents-md` only when both are needed; never put secrets or environment-specific URLs (use `CLAUDE.local.md`).

Dynamic subagent creation rules: spawn when (a) output would be verbose (tests/logs/docs), (b) the task is independent and parallelizable (per-file reviews, migrations), (c) a fresh perspective is required (review), (d) a different model/effort is cheaper. Do not spawn for sequential tasks that need the parent's context (use forks sparingly) and never nest deeper than 2. Agent teams and ultracode are opt-in experiments, not defaults.

### 3.4 Work-item state machine sketch (states, transitions, asking points)

```
NEW ──triage──▶ TRIAGED ──(ticket? move to In Progress)──▶ IN_PROGRESS
IN_PROGRESS ──clone/branch (PROJ-123-slug), worktree/container──▶ WORKSPACE_READY
WORKSPACE_READY ──Analyst──▶ SPEC_READY ──[ASK? if ambiguity score>θ]──▶ SPEC_APPROVED
SPEC_APPROVED ──Architect──▶ PLAN_READY ──[GATE: plan approval; default auto-approve after T1 if risk=low]──▶ PLAN_APPROVED
PLAN_APPROVED ──Developer (per-task subagents, TDD)──▶ IMPLEMENTED
IMPLEMENTED ──Reviewer (fresh ctx)──▶ SELF_REVIEWED ──QA (tests/lint/build)──▶ VERIFIED
VERIFIED ──PR create (template, changelog note)──▶ PR_OPEN
PR_OPEN ──(review required?) Slack thread + request reviewer──▶ REVIEW_REQUESTED
REVIEW_REQUESTED ──webhook/poll──▶ CHANGES_REQUESTED ──Developer+QA──▶ PR_UPDATED ──re-request──▶ REVIEW_REQUESTED
REVIEW_REQUESTED ──approved & checks green──▶ MERGE_READY ──[GATE: merge; default auto if policy allows]──▶ MERGED
MERGED ──Jira comment (PR link + tester instructions) + transition Testing──▶ TESTING ──Slack ping tester──▶ TESTER_NOTIFIED ──▶ DONE
Any state ──error/limit──▶ BLOCKED(reason) | PAUSED_USAGE_LIMIT(resets_at) | CANCELLED ; BLOCKED ──human answer──▶ previous state
```

Asking points (each with a recommended option backed by evidence the agent gathered — file:line, test output, doc URL, ticket text):
1. TRIAGED: "Which repo/branch?" only if ambiguous (recommended = repo with matching Jira component/history). Timeout default: recommended.
2. SPEC_READY: ≤3 clarifications (AskUserQuestion format; options from codebase evidence). Timeout: proceed with recommended if risk=low, else BLOCKED.
3. PLAN_READY: plan approval (diff-level summary, estimated tokens/time). Timeout T1 (e.g. 30 min + phone notification): auto-approve when no destructive migrations, no public API breaks, no new dependencies.
4. REVIEW: reviewer choice (recommended = CODEOWNERS/last committer of touched files; Slack presence). Timeout: post to channel without mention.
5. CHANGES_REQUESTED: ambiguous or architectural comments → ask (mirrors Claude Code auto-fix policy); clear ones → fix automatically.
6. MERGE_READY: merge gate (recommended = squash + delete branch when approvals + checks pass). Timeout: auto-merge only if policy `autoMerge=true`.
7. Jira transition name mapping on first use per project (recommended = closest match to "In Progress"/"Testing"); remembered.
8. Tester selection (recommended = ticket's QA assignee or project default). Timeout: comment without ping.
All gates are optional per work item ("no ticket", "no review", "dry-run") and every external side effect goes through a gateway with `dryRun`.

### 3.5 Human-in-the-loop rules

- Use each harness's native asking mechanism and normalize to one ByteBureau "Question" schema (question, header, options[label, description, evidence[], recommended], multiSelect, allowOther, timeout, defaultAction). Claude Code: `AskUserQuestion` via `canUseTool` (SDK) or interactive; configure `askUserQuestionTimeout` only as a fallback — ByteBureau should answer deferred questions itself with the recommended option after its own timer. Codex: app-server approval/user-input requests; OpenCode: `question` permission/`ask`; ACP `request_permission` for ACP-wrapped agents.
- Away mode: `PermissionRequest`/`Notification` hooks → push notification (phone) with deep link; if no answer in N minutes and the gate allows defaults, proceed with the recommended option and log it; for permission prompts (never auto-resolved by Claude Code) use `PreToolUse` `defer` + `claude --continue --decision allow|deny` so no process waits forever.
- Autonomy levels map to permission modes: `supervised` (default mode + sandbox auto-allow), `autonomous` (auto mode, classifier; or `acceptEdits` + allowlists), `yolo` (bypassPermissions inside a container/VM only, non-root, deny rules for `git push --force`, `rm -rf`, secrets). Deny rules apply in every mode; `ask` rules for `git push`, `gh pr merge`, Jira transitions, Slack posts.
- Steering: SDK streaming `interrupt()` + queued messages; Codex `turn/interrupt`; cloud `claude -p "msg" --cloud <id>`; `/rewind` to a cached prefix instead of compacting when abandoning a path.

## 4) Rejected options (and why)

- **Full ECC / BMAD / SuperClaude / claude-flow installs as defaults** — context-listing bloat (ECC 293 skills vs 1%-of-context budget), heavy opinionated processes overlapping ByteBureau's roster, Python installers, unverified performance claims, large issue backlogs (claude-flow 689 open).
- **SkillsMP / ClawHub / skills.sh leaderboard as auto-sync sources** — no curation; Snyk measured 36.8% flawed, 76 malicious.
- **davila7/claude-code-templates as a sync source** — aggregator with mixed provenance (fine as a browsing tool).
- **Agent teams / peer swarms as the default orchestration** — experimental, interactive-only, ~7x tokens; Anthropic's own evidence says coding has little truly parallel work.
- **Embedding the Claude Agent SDK with claude.ai login** — explicitly disallowed; keep SDK path for API keys only.
- **Multi-account rotation** — ToS violation.
- **Fast mode as a speed lever** — Opus-only, usage-credits-only on subscriptions.
- **Client-side history rewriting for compaction on Opus 5.5/Sonnet 5.5/Fable 5.1 API agents** — breaks preserved-thinking checks; use server-side compaction or Claude Code's built-in.
- **Chain-of-Draft-style "think less" prompting for coding agents** — evidence is for reasoning benchmarks; use `effort` instead.
- **Letting Claude Code marketplaces auto-update third-party skills** — bypasses ByteBureau's scan/pin pipeline.
