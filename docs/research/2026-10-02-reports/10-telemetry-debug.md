Research date: **2026-10-02**. Method: ~50 direct fetches of official docs / GitHub / npm registry / arXiv (the session's WebSearch budget was exhausted before this cluster started, so discovery was done by fetching canonical URLs, GitHub/npm JSON APIs and `llms.txt` indexes), one Claude Code docs sub-agent, and **six local empirical checks on the owner's MacBook (arm64, Node v24.14.0, Bun 1.4.2, Docker 29.8.1)**. ## 1. Executive summary

1. **Standardise on OpenTelemetry GenAI semantics, but do not depend on their stability.** In 2026 the whole `gen_ai.*` family was *moved out* of the main semconv repo (main semconv **v1.42.0, 2026-06-12** deprecated all `gen_ai.*`; latest main release **v1.44.0, 2026-08-04**) into `open-telemetry/semantic-conventions-genai`, which as of today has **no tagged release** and marks every span/metric/event **"Development"**. Agent spans (`invoke_agent`, `execute_tool`, `invoke_workflow`, `plan`), tool attributes (`gen_ai.tool.call.id/arguments/result`), cache-token attributes (`gen_ai.usage.cache_read.input_tokens`, `gen_ai.usage.cache_write.input_tokens`) and the `gen_ai.evaluation.result` event all exist and are exactly what ByteBureau needs — use the *names*, keep a thin mapping layer so renames are one-file changes. [2+]
2. **Both major coding CLIs already speak OTLP.** Claude Code exports **8 metrics + 20 event types** (tokens by `type` input/output/cacheRead/cacheCreation, cost in USD, per-request `api_request` events with cache tokens, `tool_result` with `duration_ms` and input/result byte sizes, `tool_decision`, `skill_activated`, compaction via `query_source: compact`…), over **grpc / http/json / http/protobuf / console**, with content redacted by default (`OTEL_LOG_USER_PROMPTS`, `OTEL_LOG_TOOL_DETAILS`, `OTEL_LOG_TOOL_CONTENT`, `OTEL_LOG_ASSISTANT_RESPONSES`, even `OTEL_LOG_RAW_API_BODIES=file:<dir>`), beta spans (`CLAUDE_CODE_ENHANCED_TELEMETRY_BETA=1`) and **W3C `TRACEPARENT` propagation into subprocesses and `-p` sessions**. Codex CLI has `[otel]` with `otlp-http`/`otlp-grpc` exporters, 7 event types and counters/histograms. OpenCode has no OTel but a rich plugin hook API. **ByteBureau should be the OTLP endpoint itself** (a ~200-line OTLP/HTTP-JSON receiver on `localhost`), not run an OTel Collector (contrib tarball for darwin_arm64 is ~96.7 MB) and not bundle an observability platform. [2+]
3. **Platforms: Phoenix is the only lightweight optional UI; everything else is heavy or hosted.** Arize Phoenix **20.19.0 (2026-10-01)** = one container, **SQLite by default**, OTLP on 6006/4317, imports **ATIF** trajectories, has first-party **Claude Code and Codex hook-based integrations**, but is **Elastic License 2.0** and phones home unless `PHOENIX_TELEMETRY_ENABLED=false`. Langfuse **v4.49.0** needs Postgres+ClickHouse+Redis+S3 and "at least 4 cores and 16 GiB"; Opik **2.2.87** needs MySQL+ClickHouse+Redis+MinIO+Java+Python; Laminar needs Postgres+ClickHouse+RabbitMQ; Helicone is a proxy (useless for subscription CLIs); Lunary looks **abandoned** (main repo 404, Python SDK archived); Logfire/Braintrust/Honeycomb/Weave backends are hosted/closed. Recommendation: **embed a tiny SQLite store + exporters** (OTLP forward, ATIF, JSONL, Parquet) and treat Phoenix as an opt-in `docker run`. [2+]
4. **Self-improvement loop: adopt ATIF v1.8 as the trajectory format, run the "analyst" inside Claude Code on the subscription, use `claude plugin eval` as the regression harness, and defer GEPA-style optimizers to an optional API-funded phase.** The Agent Trajectory Interchange Format (Harbor, Apache-2.0, 5.8k stars; spec `rfcs/0001-trajectory-format.md`, **ATIF-v1.8, April 2026**) is an open JSON standard already produced by Harbor's integrations for *claude-code, codex, opencode, cursor-cli, gemini-cli, openhands, swe-agent…* and importable by Phoenix. It carries per-step `metrics{prompt_tokens, completion_tokens, cached_tokens, cost_usd}`, `reasoning_effort`, `llm_call_count`, subagent trajectories, and an `extra` bag for ByteBureau's outcome signals. GEPA (paper v2 2026-02; `gepa` 6.8k stars MIT; in DSPy 3.4.0) is the state of the art for turning *textual* execution feedback into prompt edits (vs GRPO: +6 % avg, up to 35× fewer rollouts; vs MIPROv2: >10 %) and has a TypeScript sibling in **Ax (`@ax-llm/ax`, AxGEPA, Apache-2.0, 3k stars)** — but all optimizers need an API-keyed LM for reflection and a scoring function with hundreds of rollouts; TextGrad, PromptWizard and ADAS are **stale** (last push 2025). [2+]
5. **Debug/diagnostics: LogTape as the structured logger (zero deps, Bun+Node, hierarchical categories, `fingersCrossed()` flight-recorder sink, `@logtape/redaction`, rotating file + OTel sinks — all exports verified under Bun 1.4.2 and Node 24.14 locally), `--debug[=cat,!cat]` mirroring Claude Code's own syntax, OTel trace/span IDs as the correlation IDs, and a `bb diag bundle` zip modelled on Docker Desktop's `docker desktop diagnose` / `kubectl cluster-info dump` / VS Code `code --status`.** pino 10.3.1 + pino-roll 4.0.0 (worker-thread transport + redaction) also work under Bun [local] and remain the fallback if raw throughput matters.
6. **Storage: SQLite via the runtime's built-in driver (`bun:sqlite` under Bun, `node:sqlite` under Node, which is "Stability 1.2 – Release candidate" since Node 25.7), Drizzle ORM 0.45.x (1.0 is still rc/beta), WAL, FTS5 with `unicode61 remove_diacritics 2` (+ a `trigram` table for substring search).** Verified locally: Czech text "Příliš žluťoučký kůň" matches `prilis`, `zlut*` and substring `utou` in both runtimes. Caveat found locally: on macOS **Bun links Apple's system SQLite (3.54.0) built with `OMIT_LOAD_EXTENSION`**, so `sqlite-vec` needs `Database.setCustomSQLite()` (or the Node path). DuckDB `@duckdb/node-api` 1.5.6 (darwin-arm64 + linux-arm64 bindings) is the right *optional* tool for Parquet export/analytics, not the primary store. Encrypt exported bundles with `age-encryption` (typage 0.3.1) rather than encrypting the live DB; SQLite3MultipleCiphers 2.5.1 / `better-sqlite3-multiple-ciphers` 13.0.3 exist if DB-level encryption becomes a requirement (Node only, or custom dylib under Bun — *unverified*).

**Trajectory formats.**
- **ATIF — Agent Trajectory Interchange Format** (Harbor, `harbor-framework/harbor`, 5,765★, Apache-2.0, pushed 2026-10-01; spec `rfcs/0001-trajectory-format.md`, **ATIF-v1.8, April 2026**; docs accept v1.0–v1.8). File `trajectory.json`. Top level: `schema_version` (req), `session_id`, `trajectory_id` (req for embedded subagents), `agent{name (req), version (req), model_name, tool_definitions, extra}` (req), `steps[]` (req), `notes`, `final_metrics{total_prompt_tokens, total_completion_tokens, total_cached_tokens, total_cost_usd, total_steps, extra}`, `continued_trajectory_ref`, `subagent_trajectories[]` (each a complete ATIF doc), `extra`. Step: `step_id` (req, from 1), `timestamp`, `source ∈ user|agent|system` (req), `model_name`, **`reasoning_effort`**, `message` (req), `reasoning_content`, `tool_calls[{tool_call_id, function_name, arguments, extra}]`, `observation{results[{source_call_id, content, subagent_trajectory_ref{trajectory_id|trajectory_path, session_id}, extra}]}`, `metrics{prompt_tokens, completion_tokens, cached_tokens, cost_usd, prompt_token_ids, completion_token_ids, logprobs, extra}`, **`llm_call_count`** (0 = deterministic dispatch), **`is_copied_context`** ("MUST NOT be included in SFT data"), `extra`. Design notes: `prompt_tokens` = all input tokens incl. cached, `cached_tokens` = cache-hit subset; **no per-token pricing stored** (pricing drifts); audio by path only. Harbor's pre-integrated agents with ATIF capability include **claude-code, codex, opencode, cursor-cli, gemini-cli, copilot-cli, cline-cli, openhands, swe-agent, terminus-2, goose, mini-swe-agent…**; Harbor keeps native logs too (Claude Code `agent/sessions/projects/-app/<session-id>.jsonl`, Codex `agent/sessions/<YYYY>/<MM>/<DD>/rollout-*.jsonl`) and converts ATIF ↔ native for cross-agent "trajectory seeding" (`--load-trajectory`). Phoenix imports ATIF. [2+]
- **SWE-agent `.traj`**: `trajectory[]{action, observation, response, thought, state, query}`, `history[]`, `info{model_stats{instance_cost, tokens_sent, tokens_received, api_calls}, exit_status, submission}`, `environment`. Older, agent-specific. [1]
- **OTel GenAI events** (`gen_ai.client.inference.operation.details` + `gen_ai.input/output.messages` JSON) — per-call, not per-task; fine for forwarding, poor as the analyst's canonical input.
- Langfuse export (CSV/JSON/API), Claude Code transcript JSONL, Codex rollout JSONL — vendor-specific.

**Verdict**: ATIF v1.8 is the only open, multi-agent, actively maintained trajectory standard with token/cache/cost per step and subagent nesting; its `extra` fields are the sanctioned place for ByteBureau's task metadata and outcome signals.

## 3. Ranked recommendations + risks

### 3.1 Telemetry architecture (what is emitted, where it goes, how it is exported)

**R1 — Embed, don't bundle.** ByteBureau owns a single SQLite file (`~/.bytebureau/bb.db`, WAL) and is itself the telemetry sink:
1. **Internal instrumentation** with `@opentelemetry/api` 1.9 + `sdk-trace-base` 2.11 + `AsyncLocalStorageContextManager` (**manual spans only; never `auto-instrumentations-node`** in Bun). One tracer; GenAI names: `invoke_workflow <flow>` (ticket→PR flow), `invoke_agent <role>` per agent run, `execute_tool <name>` for ByteBureau-side tools (git, gh, jira, slack, docker), `chat <model>` only for ByteBureau's *own* model calls (summaries/judges). A custom `SpanProcessor` writes finished spans straight into SQLite (no exporter round-trip); the OTLP/HTTP exporter is enabled only when the user configures a forward target.
2. **OTLP/HTTP receiver** inside ByteBureau (`http://127.0.0.1:<port>/v1/{logs,metrics,traces}`, JSON *and* protobuf — protobuf via `@opentelemetry/otlp-transformer` decoders, JSON via the OTLP JSON mapping). When ByteBureau spawns an agent it sets per-process env: Claude Code → `CLAUDE_CODE_ENABLE_TELEMETRY=1 OTEL_LOGS_EXPORTER=otlp OTEL_METRICS_EXPORTER=otlp OTEL_EXPORTER_OTLP_PROTOCOL=http/json OTEL_EXPORTER_OTLP_ENDPOINT=http://127.0.0.1:<port> OTEL_LOGS_EXPORT_INTERVAL=1000 OTEL_METRIC_EXPORT_INTERVAL=10000 OTEL_RESOURCE_ATTRIBUTES=bb.task_id=…,bb.agent_run_id=…,bb.role=…,bb.variant=…` (+ `OTEL_LOG_TOOL_DETAILS=1` always; `OTEL_LOG_USER_PROMPTS/ASSISTANT_RESPONSES/TOOL_CONTENT` per the user's consent setting; `TRACEPARENT` for correlation; `CLAUDE_CODE_ENHANCED_TELEMETRY_BETA=1 OTEL_TRACES_EXPORTER=otlp` optional). Codex → `[otel] exporter = { otlp-http = { endpoint, protocol = "json" } } metrics_exporter = "otlp-http" log_user_prompt = <consent>` in a per-run `CODEX_HOME` config, plus `notify`/hooks. OpenCode → a ByteBureau plugin posting to the same receiver. Inside containers the endpoint is `host.docker.internal` / the bridge IP.
3. **Hook/stream taps** are the primary trajectory source (they are the documented, stable surfaces): Claude Code hooks (`UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `SubagentStart/Stop`, `PreCompact/PostCompact`, `Stop`, `SessionEnd`, `PermissionRequest`) + `-p --output-format stream-json` (`result.modelUsage`, `num_turns`, `duration_api_ms`, `permission_denials`); Codex hooks/`notify` + rollout JSONL; OpenCode plugin hooks. OTLP events add what hooks lack (per-request tokens/cost/cache, `effort`, `speed`, `tool_result_size_bytes`, `api_retries_exhausted`, `skill_activated`, `query_source: compact`). Transcript-file parsers (Claude `~/.claude/projects/*.jsonl`, Codex `rollout-*.jsonl`) are **best-effort importers only** (internal formats).
4. **Export surfaces**: (a) `bb export trajectory <task> --format atif|jsonl` (ATIF v1.8 with ByteBureau `extra`), (b) `bb export otlp --to <url>` or live forwarding (Phoenix/Langfuse/any OTLP), (c) `bb export parquet` via optional DuckDB (`COPY (SELECT …) TO 'x.parquet'`) for the analyst, (d) `bb diag bundle` (section 3.4).
5. **Metrics kept locally** (derived, SQLite views): tokens by type/model/role/skill/variant, cost (from `claude_code.cost.usage`/`api_request.cost_usd` or a *versioned* price table — ATIF deliberately stores no prices), tool-call counts/durations/sizes, retries, compactions, human interventions, wall time, and **outcome-normalised ratios**: tokens per merged PR, tokens per review comment resolved, cost per green CI, rework commits per PR, time-to-merge.

*Risks*: GenAI semconv may rename again (mitigate: one mapping module + `bb.semconv_version` on every row); Claude Code's beta tracing endpoints may change; OTLP/JSON encoding details (int64 as strings, attribute `AnyValue` shape) need a small conformance test; Codex defaults `metrics_exporter=statsig` (set explicitly to `none`/otlp to avoid silent phone-home); if ByteBureau drives Claude Code with the user's claude.ai login, the quoted SDK policy ("Anthropic does not allow third party developers to offer claude.ai login") must be reviewed by the owner (see §5).

### 3.2 Trajectory data model (SQLite + ATIF export)

```

agent_runs(run_id PK, task_id FK, role, role_prompt_hash, agent_kind {claude-code|codex|opencode|local}, model, effort, speed, permission_mode,
           variant_id, skill_set_hash, container_image, started_at, ended_at, exit_reason, trace_id, session_id_external)
turns(turn_id PK, run_id FK, seq, source {user|agent|system}, started_at, ended_at, prompt_id, message_text?, reasoning_text?,
      llm_call_count, input_tokens, output_tokens, cache_read_tokens, cache_write_tokens, cost_usd, model, stop_reason,
      is_compaction, is_human_intervention, intervention_kind {reprompt|answer|abort|permission})
tool_calls(call_id PK, turn_id FK, tool_name, tool_kind {builtin|mcp|bash|skill|subagent}, args_json?, args_bytes, result_bytes,

llm_calls(call_id PK, turn_id FK, request_id, model, attempt, duration_ms, ttft_ms, input_tokens, output_tokens, cache_read_tokens,

         value_num, value_text, category, at)                                                                       -- time-series of signals
events(event_id PK, ts, trace_id, span_id, run_id?, category, level, name, attrs_json)                              -- raw OTLP logs + bb log
```

Required dimensions for the analyst: ticket, role prompt + skill versions (hash + content snapshot in `artifacts`), model/effort/speed, every turn's prompt/tool calls/result sizes/tokens (in/out/cache read/cache write)/latency/errors/retries, human interventions and re-prompts, asking-dialog answers (`intervention_kind=answer` + text), compaction events (`is_compaction`, `query_source=compact`), and outcome signals (tests, lint, PR opened, review comments count/category, time-to-merge, rework commits, user satisfaction 1–5). Privacy: `message_text`, `args_json`, `result_text` are **nullable and governed by a consent level** (`off` = sizes/hashes only, `local` = stored but never exported without `--include-content`, `full`); redaction runs *before* insert (field + pattern scanners) and again at export.

**ATIF mapping**: `agent_runs` → ATIF document (`agent{name: "claude-code", version, model_name}`; `session_id` = task id; `trajectory_id` = run id); `turns` → `steps` (`source`, `message`, `reasoning_content`, `reasoning_effort`, `llm_call_count`, `metrics{prompt_tokens = input+cache_read+cache_write, cached_tokens = cache_read, completion_tokens, cost_usd}`); `tool_calls` → `tool_calls[]` + `observation.results[]` (subagents → `subagent_trajectories` with `subagent_trajectory_ref`); task/role/skill/variant/outcome data → `extra.bytebureau{ticket, role, role_prompt_hash, skills[{name,version,hash}], variant_id, interventions[], outcomes[]}`; `final_metrics` from sums. Keep `is_copied_context=true` for seeded context steps.

### 3.3 Self-improvement loop (practical for a solo dev on a subscription)

**R2 — Phase 1 (no API spend): "collect → aggregate → analyst skill".** `bb report analysis --since 30d` writes an *analysis bundle*: `summary.json` (per role/skill/variant/model: tasks, success rate, tokens by type, cost, tool-call mix, retries, compactions, interventions, outcome ratios, top failure categories), `trajectories/*.atif.json` (stratified sample: best, worst, most expensive, most interventions), `artifacts/` (current role prompts, skills, flows with versions), and `report-prompt.md`. The owner runs the **analyst prompt inside Claude Code** (a `/bb-analyze` skill in the ByteBureau plugin; subscription-funded). Analyst prompt outline:
1. Role: senior prompt/agent-ops engineer; goal: *maximise outcome quality per token*; never propose changes that reduce test pass / review quality.
2. Inputs: `summary.json` schema, ATIF schema, artifacts; instructions to read aggregates first, then sampled trajectories, then cross-check claims against ≥3 trajectories.
3. Required analysis: (a) token sinks (largest tool results, repeated file reads, verbose system prompts, unused skills via `skill_activated` vs loaded), (b) failure/rework patterns (lint/test loops, review comment categories), (c) intervention triggers (what the human had to re-prompt), (d) compaction/context pressure, (e) variant comparison with uncertainty (n, CI), (f) model/effort fit per role.
4. Output contract (machine-readable): `findings[] {id, evidence: [trajectory_id/step_id…], metric_delta_expected, confidence}`, `changes[] {target: role_prompt|skill|flow|config, path, diff (unified), rationale, risk, rollback}`, `experiments[] {hypothesis, variant spec, success metric, sample size}`, `open_questions[]`.
5. Constraints: cite step ids; prefer deleting/shortening over adding; one change per finding; estimate token impact.
Then **gate every change through `claude plugin eval`** (regression suite with `tool_order`/`file_exists`/`llm`/`baseline` graders) and ship as a new `variant_id`.
**R3 — Phase 2: built-in A/B.** Variants = immutable bundles (role prompt + skills + flow + model/effort) assigned per task by seeded randomisation (or interleaving by ticket parity); report per-variant outcome ratios with bootstrap CIs; auto-promote only on human approval. Minimum sample guard (≥10 tasks/variant) to avoid noise.
**R4 — Phase 3 (optional, API-keyed): offline optimisation.** Export ATIF → (a) **Ax `AxGEPA`** in TypeScript for role prompts/skill text, with a metric that replays cheap proxies (lint/test pass on a fixed task set in containers, judge via `@arizeai/phoenix-evals` or promptfoo `llm-rubric`) and returns *textual feedback* (GEPA's requirement); or (b) `gepa` (Python) with a TerminalBench-style adapter. Budget: GEPA's own "light" budget is hundreds of rollouts — only worth it for the highest-traffic role.
*Risks*: judge/optimiser cost; overfitting to a small task set (keep a held-out set); subscription ToS for automated headless runs; "improvement" measured on proxies ≠ real PR quality (always report merged-PR metrics).

### 3.4 Debug / diagnostics design

**R5 — Logger: LogTape** (zero deps, Bun+Node parity, categories = subsystems, OTel sink shares trace context). Category tree `bb.core`, `bb.flow`, `bb.agent.{claude,codex,opencode,local}`, `bb.container`, `bb.vcs`, `bb.tracker`, `bb.slack`, `bb.ui`, `bb.store`, `bb.otlp`. Default sinks: pretty console (warn+ in UI mode), rotating JSONL file `~/.bytebureau/logs/bb.log` (`maxSize 20 MB`, `maxFiles 5`), **`fingersCrossed()` ring buffer** holding `debug` records (e.g. 5,000 / per task) released on `error` or on demand — the "flight recorder". Fallback: pino 10 + pino-roll (verified in Bun) if LogTape throughput ever becomes the bottleneck.
**Flags/env**: `--debug` (all categories to debug, file sink + `--log-file <path>`), `--debug=flow,agent.claude,!ui` (filter syntax mirrors Claude Code), `BB_DEBUG=core:*,sim:*` (debug-style namespaces, same matcher), `--log-level`, `BB_LOG_FORMAT=json|pretty`, `--trace-console` (OTel ConsoleSpanExporter), `BB_VERBOSE_FETCH=1` → sets `BUN_CONFIG_VERBOSE_FETCH=curl` for the process; `--debug` also lowers Claude Code's export intervals and adds `--debug-file` to spawned CLIs, and sets `RUST_LOG=codex_core=debug` + `log_dir` for Codex and `--log-level DEBUG` for OpenCode, collecting their files into the task directory.
**Correlation IDs** = OTel ids: `trace_id` per task, span per agent run/turn/tool call; LogTape implicit context carries `trace_id/span_id/task_id/run_id/turn_id`; W3C `traceparent` to subprocesses (`TRACEPARENT` env; Claude Code honours it), to containers (env) and to HTTP MCP servers.
**Redaction**: sink-level `@logtape/redaction` field list (`authorization`, `cookie`, `set-cookie`, `password`, `token`, `api_key`, `apikey`, `secret`, `client_secret`, `private_key`, `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GH_TOKEN`, `SLACK_BOT_TOKEN`, `JIRA_API_TOKEN`) + pattern scanners (`sk-ant-…`, `sk-…`, `ghp_/github_pat_…`, `xox[abp]-…`, `AKIA…`, JWT `eyJ…`, `-----BEGIN … PRIVATE KEY-----`, URL userinfo); same rules applied to OTLP attributes on ingest and to the bundle at export; unit tests with canary secrets.
**`bb diag bundle [--include-content] [--since 24h] [--task <id>]`** → `bb-diag-<ts>-<shortid>.zip` in the temp/Downloads dir, printed path + id, **never auto-uploaded**; shows a file list and asks for confirmation (consent-first, like Docker's diagnostic ID flow). Contents: `manifest.json` (bb version/commit, Bun/Node version, OS/arch, Docker version, enabled plugins, locale, timezone, consent level), `config.redacted.json` + `settings-sources.txt`, `env.redacted.txt` (allowlisted keys only), `logs/` (last N MB per category + flight-recorder dump), `events.jsonl` (recent OTLP events, redacted), `spans.jsonl` (recent traces), `tasks/<id>/` (ATIF trajectory w/o content unless `--include-content`, agent CLI debug logs, container `inspect` + last 500 log lines, git status/diff --stat), `system/` (CPU/mem/disk, `docker info`, `process.report.getReport()` on Node / `v8.getHeapStatistics()` on Bun), `ui/` (optional screenshots), `health.json` (the same checks `bb doctor` runs: paths writable, DB integrity_check, docker reachable, agent CLIs on PATH with versions, OTLP receiver port). `bb doctor` prints the health checks interactively (modelled on `claude doctor`, VS Code `code --status`).
**Performance marks**: `performance.mark/measure` around flow stages feed OTel histograms (`bb.flow.stage.duration`, `bb.agent.run.duration`, `bb.tool.duration`) — `perf_hooks` marks/measures are implemented in Bun; `eventLoopUtilization()` is not (returns zeros), so skip ELU metrics under Bun.
**Crash path**: uncaught error → flush fingers-crossed buffer → write `crash-<ts>.json` (error, last 200 events, versions) → suggest `bb diag bundle`. Source maps: ship `--sourcemap` in compiled binaries so crash stacks are readable.
*Risks*: LogTape is a one-maintainer project (mitigate: logger façade, ≤1 day to swap to pino); Bun's `Worker`/ALS propagation gaps if logging from worker threads (pass ids explicitly); over-collection — keep content opt-in and show the bundle listing before writing.

### 3.5 Local storage

**R6 — SQLite via the runtime driver behind a 50-line adapter** (`bun:sqlite` when `typeof Bun !== "undefined"`, else `node:sqlite`; both synchronous, both have FTS5/JSON/Session compiled in on macOS as verified). **Drizzle ORM 0.45.x** (stable; `drizzle-orm/bun-sqlite` + `drizzle-orm/node-sqlite`) with `drizzle-kit generate` migrations embedded and applied at startup via `migrate()`; move to 1.0 once GA. PRAGMAs: `journal_mode=WAL`, `synchronous=NORMAL`, `busy_timeout=5000`, `foreign_keys=ON`; one writer process (the ByteBureau daemon), readers may be UI processes.
**Search**: FTS5 external-content table over messages/tool results with `tokenize='unicode61 remove_diacritics 2'` (`bm25()` ranking, `snippet()` for hits), `prefix='2 3'`; a second small `trigram` table for substring/identifier search (`remove_diacritics 1`, `case_sensitive 0`). Czech has no FTS5 stemmer — diacritics folding + prefix queries + trigram cover most needs; optional **semantic search** with `sqlite-vec` 0.1.9 + local embeddings (Ollama) **only when extension loading is available** (Node path, or Bun with `Database.setCustomSQLite(<Homebrew libsqlite3>)`; on Linux/RPi Bun bundles its own SQLite — test `loadExtension` at startup and degrade gracefully).
**Retention/compaction**: raw tool results capped (e.g. 32 KB stored, full size recorded), `events/spans` TTL 30 days (configurable), trajectories kept until the task is `archived`; nightly `bb store compact` (delete expired, `PRAGMA incremental_vacuum`/`VACUUM INTO backup`), monthly Parquet roll-up of aggregates (optional DuckDB).
**Analytics/export**: `@duckdb/node-api` 1.5.6 as an *optional* dependency (`bb export parquet`, ad-hoc SQL over JSONL/Parquet/SQLite via DuckDB's `sqlite` scanner); never required at runtime. Prefer `hyparquet-writer`/`parquet-wasm` if DuckDB must be avoided on constrained devices.
**Encryption at rest**: default none (local-first, OS disk encryption); `bb export … --encrypt` uses `age-encryption` (X25519 recipient or passphrase) for bundles/trajectories leaving the machine; DB-level encryption (SQLite3MultipleCiphers via `better-sqlite3-multiple-ciphers` on Node; custom dylib for Bun — *unverified*) only if a user demands it.
*Risks*: `node:sqlite` is RC (API still printing ExperimentalWarning on 24.x); Bun-on-macOS system SQLite forbids extensions; Drizzle 1.0 churn (rc since June); DuckDB native binary ~tens of MB per platform (keep optional); FTS5 trigram index size (≈3–4× text) — enable per table only.

## 4. Rejected options (and why)

- **OTel Collector as a required component** — adds a ~100 MB binary/process and YAML for a single receiver; ByteBureau can host OTLP/HTTP itself. Keep only as documentation for users who already run one.
- **OTel auto-instrumentation (`@opentelemetry/auto-instrumentations-node`, OpenLLMetry-JS)** — depends on module patching and `diagnostics_channel` channels Bun lacks (open issues #26536/#29586/#32472); ByteBureau's model calls happen inside third-party CLIs anyway.
- **Bundling Langfuse / Opik / Laminar** — 4–7 services each (ClickHouse, Postgres/MySQL, Redis, MinIO, RabbitMQ…), 16 GiB class hardware for Langfuse; incompatible with "local-first, Raspberry Pi 5".
- **Helicone** — proxy/gateway model cannot observe subscription-authenticated CLI traffic.
- **Lunary** — main repo 404, Python SDK archived; unmaintained.
- **Logfire, Braintrust, Honeycomb, Keywords AI, Openlayer, W&B Weave backend** — hosted/closed backends; conflict with local-first and privacy.
- **MLflow 3 tracing as the store** — Python server; TS SDK 0.1.3 pinned to an old OTel SDK.
- **TextGrad, PromptWizard, ADAS, OpenAI Evals, AutoGen AgentOptimizer** — stale (2025 or older pushes) or API-spend-centric benchmark registries.
- **Agent Lightning / SICA-style self-modification** — RL+GPU infrastructure or self-editing code; wrong risk profile for a solo maintainer.
- **winston, consola (as backend), `debug`** — no structured/OTel story; `debug`'s namespace syntax is adopted for `BB_DEBUG`, the library is not.
- **Prisma** — now 8.0-rc with driver adapters only; heavier than needed; no `node:sqlite` adapter.
- **PGlite / chdb / LanceDB as primary store** — WASM Postgres or ClickHouse engines add tens of MB and a second query dialect; SQLite+FTS5 covers chat search; LanceDB only if vector search outgrows sqlite-vec.
- **DB-level encryption by default (SQLCipher/SQLite3MultipleCiphers)** — forces a custom SQLite build on both runtimes; file/bundle-level `age` encryption gives the privacy win for exported data.
- **Parsing agent transcript files as the primary source** — Claude Code's JSONL is documented as internal; hooks/stream-json/OTLP are the supported surfaces.
