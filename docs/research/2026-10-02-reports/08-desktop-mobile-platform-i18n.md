## 1. Executive summary

**Architecture recommendation (one core, three shells):**

1. **Core = one Bun-compiled server binary per platform** (`bytebureau`), which contains the CLI, the HTTP/WebSocket API, the agent orchestrator and the *static web UI*. `bytebureau` (no args) starts the server and opens the browser; `bytebureau --headless` is the Raspberry Pi / server mode. Bun 1.4.2 cross-compiles to linux x64/arm64 (glibc + musl), windows x64/arm64, darwin x64/arm64 from one machine (✅). Expect **60–80 MB per uncompressed binary**; Tauri installers that embed such a sidecar land at **28–41 MB** (✅ two independent write-ups).
2. **Desktop = Tauri 2.12** shell that bundles the core as a **sidecar** and otherwise only hosts the same web UI in the OS webview. Tauri 2.12.0 shipped 2026-09-26 (✅), has first-party plugins for notification, updater (signed, GitHub-Releases static JSON), deep-link, single-instance, autostart, store, window-state (✅), and `tauri-action` v1.0.0 (2026-06-29) builds + publishes all three OSes incl. Linux arm64 on free GitHub arm runners (✅). **Do not use Electron** (44.5.1, Chromium 152, hundreds of MB) or Electrobun (2.0.2, single maintainer, Windows arm64 beta without JIT, no notifications per March-2026 review).
3. **Mobile = PWA first** (served by the core; installable; Web Push with VAPID works on iOS when added to Home Screen — and since iOS 26 *every* Home-Screen site opens as a web app ✅), reached through a **relay** (Paseo/Happy-style end-to-end-encrypted relay, or Tailscale Serve/Funnel for zero-infra). A store app (Expo SDK 57/58, New Architecture only) is a later, optional step; the two best open-source precedents (Happy, Paseo) both use **Expo** for mobile.
4. **CLI/TUI = Bun-native.** Arg parsing with `citty` (zero-dep, `util.parseArgs`) or `commander` 15 (ESM-only); prompts with `@clack/prompts` 1.8.1 (accessible mode, taskLog, streams); rich full-screen TUI (if ever needed) with **OpenTUI 0.5.14** (Zig core, React/Solid renderers, runs on Bun 1.3+ or Node 26.4+ with `--experimental-ffi`; used by OpenCode in production). Agent-friendly surface: `--json` / `--output-format json|stream-json` (JSONL events, the Claude Code & Codex convention), `--non-interactive`/`--yes`, TTY detection, `NO_COLOR`, stable exit codes, `bytebureau completions <shell>`.
5. **Install/update:** `curl -fsSL https://bytebureau.dev/install | sh` + PowerShell `irm | iex` (Bun/uv/Deno pattern, download from GitHub Releases, SHA-256 + GitHub artifact attestation), `npx/bunx bytebureau` via esbuild-style per-platform optionalDependencies, Homebrew tap (automated with `homebrew-releaser`), Scoop bucket, winget manifest, `mise use github:bytebureau/bytebureau` (works with zero plugin work, verifies attestations by default ✅), `docker run ghcr.io/…` multi-arch (native arm runners). Self-update: `bytebureau upgrade` (deno/uv pattern: GitHub Releases + checksum + atomic replace; disabled when installed by a package manager), desktop via Tauri updater.
6. **Keep-awake** belongs in the **core** (so it works headless/CLI/Pi): macOS `caffeinate -i -w <pid>` / `IOPMAssertionCreateWithName`, Linux `systemd-inhibit --what=idle:sleep` (D-Bus `org.freedesktop.login1`), Windows `SetThreadExecutionState(ES_CONTINUOUS|ES_SYSTEM_REQUIRED)`. The Rust `keepawake` crate 0.6.1 (2026-08-20) wraps all three for the Tauri shell; the only Tauri plugin for it (`tauri-plugin-keepawake` 0.1.1, Jan 2025) has a **404'd GitHub repo** ⚠ — write a ~100-line in-house plugin around `keepawake` instead. In Node/Bun, `pervigil` 0.6.0 (June 2026, zero deps) implements the same spawn-a-child pattern but is brand new ◐.
7. **Notifications + sound:** browser Notifications API (user gesture, service-worker `showNotification`), Tauri notification plugin 2.5.1 (all 5 platforms; Windows only when installed), CLI: OSC 9 toast (iTerm2, WezTerm, Kitty, Ghostty ✅) + BEL fallback + optional `terminal-notifier`/`notify-send`/PowerShell toast; sounds via `afplay`/`paplay`/`aplay`/PowerShell from the core and Web Audio in the UI. `node-notifier` is stale (2022) ⚠.
8. **i18n:** **Paraglide JS 2.25.4** (compile-time, tree-shaken, framework-agnostic, Intl.PluralRules variants — fits Czech's 4 plural forms) for UI *and* CLI strings; keep ICU MessageFormat 1 syntax via plugin if translators need it; **do not bet on MessageFormat 2** (Intl.MessageFormat still Stage 1–2, `i18next-mf2` ~10 downloads/week ✅). Dates: Temporal is Stage 4 and shipped in Firefox 139 / Chrome 144 / Node 26, **not in Safari** ✅ → use `temporal-polyfill` 1.0.5 or `@internationalized/date`; `Intl.DurationFormat`/`RelativeTimeFormat` are Baseline.
9. **Accessibility/font scaling:** root `font-size` as a percentage multiplier of the user's browser default + `rem` everywhere (WCAG 1.4.4 200 %), honour `prefers-reduced-motion`, `prefers-contrast`, `forced-colors`; WCAG 2.2 adds 24×24 px targets and focus-not-obscured. The pixel-art office is a canvas → keep it decorative/optional with a parallel DOM for all information.

**Biggest risks:** (a) **Code signing**: Apple notarization needs the $99/yr program (free tier cannot notarize ✅); Azure Artifact Signing's *individual* Public-Trust validation is **US/Canada-only** (EU organisations are eligible) and needs a paid Azure subscription ✅, EV certs no longer bypass SmartScreen ✅ — so Windows will show SmartScreen warnings until reputation builds unless a Czech company entity signs. (b) **WebKitGTK on Linux** (distro-dependent, WebGPU status unknown ◐) — design the office renderer for Canvas2D/WebGL, not WebGPU. (c) **Tauri 3.0 alpha** started 2026-09-15 ✅ — stay on 2.x, expect a migration in 2027. (d) **Bun binary size** per platform (~60–80 MB uncompressed) and the fact that the sidecar is stored uncompressed inside Tauri bundles (installers compress it).

**Agent-friendly CLI conventions (✅ clig.dev + gh + Claude Code + Codex + OpenCode docs):**
- `--json` (gh: `--json <fields>`, `--jq`, `--template`, pretty-print only on TTY); clig.dev: `--plain` for grep-able tables, `--no-input` to disable prompts, prompt only when stdin is a TTY, zero/non-zero exit codes mapped to failure modes, `-h/--help` leading with examples, disable colour/animation when not a TTY / `NO_COLOR` / `TERM=dumb` / `--no-color`, config precedence flags > env > project > user > system, XDG dirs, output within 100 ms, graceful Ctrl-C.
- **Claude Code** (`code.claude.com/docs/en/cli-reference`): `-p/--print`, `--output-format text|json|stream-json`, `--input-format text|stream-json`, `--json-schema` (validated structured output), `--max-turns`, `--max-budget-usd`, `--permission-mode`, `--bare`, `--verbose`; `claude auth status` prints JSON and exits 0/1; `claude agents --json`; `claude ultrareview --json` (exit 0/1).
- **Codex** (`codex exec`): `--json` → JSON Lines events (`thread.started`, `turn.completed`, `item.completed`), `--output-schema`, `-o <file>` last message, `--sandbox read-only|workspace-write|danger-full-access`, `--ephemeral`, `codex exec resume --last`.
- **OpenCode**: `opencode run --format json`, `--print-logs`, `--attach`; `opencode serve --port --hostname --mdns` (+ `OPENCODE_SERVER_PASSWORD`), `opencode web`.
- **NO_COLOR** spec: present & non-empty disables colour; CLI flags and user config override it.
- Terminal notifications from a CLI: see §2.5.

What makes 2026 CLIs feel "nice" (observed in the docs above): examples-first help, consistent `--json` + JSONL streaming for agents, QR codes for pairing (Claude Code `remote-control` shows a QR; Happy pairs via QR), `doctor` commands, `upgrade` built in, named sessions, `--name`, "Did you mean …" suggestions (Claude Code), accessible/screen-reader mode (`claude --ax-screen-reader`, clack accessible mode).

### 2.3 Installation & single-command start

**Reference installers (✅):**
- **Bun** `install.sh`: `uname -ms` → `darwin-x64|darwin-aarch64|linux-x64|linux-aarch64` (+`-musl` on Alpine, `-baseline` without AVX2), Windows → PowerShell `install.ps1`; downloads `github.com/oven-sh/bun/releases/latest/download/bun-$target.zip` (or a pinned tag as `$1`); **no checksum/signature verification** (HTTPS only); installs to `~/.bun/bin`, appends `BUN_INSTALL`/`PATH` to `.bashrc`/`.zshrc`/fish config. `bun upgrade` (+`--canary`/`--stable`); brew/scoop users use those managers. Platforms: Linux x64/arm64 (glibc 2.17+, kernel 5.6+ recommended, 3.10 min), Windows 10 1809+ x64/arm64, macOS 13+ x64/arm64; Docker `oven/bun` (debian/slim/distroless/alpine).
- **uv**: `curl -LsSf https://astral.sh/uv/install.sh | sh` / `irm … | iex`, plus pipx/brew/winget/scoop/cargo/Docker/GitHub Releases; `uv self update` only for the standalone installer (disabled for package-manager installs); `UV_NO_MODIFY_PATH=1`.
- **Deno** `deno upgrade`: GitHub Releases, channels (`lts`/`rc`/`canary`), exact versions, `--output`, **checksum verification and delta updates**, dry-run.
- **mise** (v2026.9.18): `mise use github:owner/repo` installs from GitHub Releases with automatic OS/arch/libc asset scoring, optional `asset_pattern`, SHA-256 `checksum`, **GitHub Artifact Attestations verified by default**, SLSA options, `mise.lock` — **no plugin needed** ✅. `ubi` v0.12.0 (same idea, Apache/MIT; no checksum verification per README ◐). `cargo-binstall` v1.24.0 (Rust-centric, GPL-3.0). **cargo-dist/"dist"** v0.33.0 (2026-09-11, Apache/MIT, 2.1k★): generates shell/PowerShell/Homebrew/npm/MSI/pkg installers + GitHub Actions release workflow + checksums/attestations and **supports generic (non-Rust) builds** ✅ — a credible way to get the whole installer matrix for a Bun binary.

(`brew bump-formula-pr` is for homebrew-core — not needed.)
- **winget**: PR to `microsoft/winget-pkgs` (sparse checkout, one package-version per PR), YAML manifest schema 1.12.0 via `wingetcreate`, automated validation (hash, URL reputation, Defender scan, silent install), human moderation; installer URL must come directly from the publisher's release location (GitHub Releases is accepted), SHA-256 required, `Architecture: x64|arm64`. Minimal schema lists `InstallerType` exe/msi/msix/inno/wix/nullsoft/appx/font; `portable`/`zip` (NestedInstallerType) types exist in the installer schema ◐ (not shown on the fetched page).
- **Scoop**: a bucket = git repo of JSON manifests (`version`, `url`, `hash`, `bin`, `checkver`/`autoupdate`), BucketTemplate with GitHub Actions ✅.
- **Docker**: `docker/build-push-action` with `platforms: linux/amd64,linux/arm64` via QEMU, or Docker's reusable `build.yml` that farms arm builds to `ubuntu-24.04-arm` runners ✅; base `oven/bun:distroless|alpine`.
- **Supply chain**: npm `--provenance`/trusted publishing (Sigstore, `id-token: write`), GitHub `actions/attest-build-provenance` + `gh attestation verify` (SLSA v1.0 Build L2; public repos use Sigstore public instance) ✅. Recommend: SHA256SUMS + attestation on every release asset; installer verifies SHA-256 at minimum; document `gh attestation verify`.
- **`npx bytebureau` / `bunx`**: esbuild pattern — main package lists per-platform packages in `optionalDependencies` (`@bytebureau/cli-darwin-arm64`, …); npm installs only the matching one; a postinstall fallback downloads if `--no-optional` ✅. Claude Code itself ships both npm and a native `claude install [stable|latest]` path (docs) — same hybrid.
- **Background service**: macOS launchd user agent in `~/Library/LaunchAgents` (`Label`, `ProgramArguments`, `RunAtLoad`, `KeepAlive`, `StandardOutPath`; `launchctl bootstrap gui/<uid> …`) ✅; Linux `systemd --user` unit + `loginctl enable-linger` (standard practice; Arch wiki fetch was blocked by Anubis, so **not re-verified today** ◐; `systemd-inhibit` man page ✅); Windows `schtasks /create /sc onlogon /tn ByteBureau /tr "…\bytebureau.exe serve"` ✅ (Microsoft doc notes only Administrators can schedule tasks under `/ru System`; user-level logon tasks are the normal path). Desktop shell: Tauri `autostart` plugin 2.7.0.
- **"One command opens the browser UI"**: core starts on `127.0.0.1:<port>` (default port + `get-port` fallback), prints URL + QR, opens with `open` (`xdg-open`/`start` underneath); `--host 0.0.0.0` requires an auth token (OpenCode uses `OPENCODE_SERVER_PASSWORD`); LAN/VPN exposure via **Tailscale Serve** (tailnet-only, HTTPS certs issued automatically) or **Funnel** (public; ports 443/8443/10000; relay never decrypts; needs `funnel` node attribute) ✅.
- **Raspberry Pi 5 (arm64)**: Bun `linux-arm64` glibc build + `oven/bun` arm64 images; Tauri desktop on Pi is possible (WebKitGTK) but heavy — target **headless** there.

### 2.6 Keep-awake

- **OS primitives (✅ vendor docs):**
  - macOS `caffeinate`: `-d` display, `-i` idle sleep, `-m` disk, `-s` system sleep (**AC power only**), `-u` user-active, `-t <sec>`, `-w <pid>`; underlying API `IOPMAssertionCreateWithName`.
  - Linux `systemd-inhibit --what=idle:sleep --mode=block --why="ByteBureau session running" <cmd>` (D-Bus `org.freedesktop.login1.Manager.Inhibit`); desktop-level `org.freedesktop.ScreenSaver.Inhibit` for the screen.
  - Windows `SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED [| ES_DISPLAY_REQUIRED])`: thread-scoped, must be cleared with `ES_CONTINUOUS`, **cannot block user-initiated sleep/lid close**, doesn't stop the screensaver; `ES_AWAYMODE_REQUIRED` only for media apps.
  - Electron's `powerSaveBlocker` semantics (`prevent-app-suspension` vs `prevent-display-sleep`, display wins) are a good API model.
- **Rust:** `keepawake` crate **0.6.1 (2026-08-20)**, MIT, 241k downloads, repo `segevfiner/keepawake-rs` (48★, pushed 2026-09-01): IOPMAssertion / SetThreadExecutionState / D-Bus ScreenSaver + logind inhibit; options `display`, `idle`, `sleep`, app name/reason ✅. Tauri wrappers: `tauri-plugin-keepawake` 0.1.1 (2025-01-14, Tauri ^2.1, depends on keepawake ^0.5.1, desktop only) — **GitHub repo returns 404 as of today** ⚠; `tauri-plugin-nosleep` 0.1.0 (2024-02, 23★, last push 2024-03) ⚠. → Write an in-house Tauri command around `keepawake` (≈100 LOC) or, simpler, let the **core** own the inhibitor so desktop/CLI/headless behave identically.
- **Node/Bun:** `pervigil` 0.6.0 (2026-06-26, MIT, zero deps): spawns `caffeinate` / `systemd-inhibit` (falls back to `/sys/power/wake_lock`) / PowerShell `SetThreadExecutionState`; separate system vs display axes; fail-safe no-op in containers; auto-release on exit; TypeScript; `pervigil/testing` mock ◐ (single author, 3 months old). Older npm packages `caffeine` (2012), `stay-awake` (2015, GPL-2), `keep-awake` (2021) are dead ⚠. Precedents: `@narumitw/pi-caffeinate` (Pi agent extension "keeps the computer awake while the agent is running"), `dsh-power-awake`, OpenClaw issue #152388 asking for a consistently named, default-off, device-local "Keep computer awake" setting across its Tauri and native apps (in progress) ✅.
- **Browser/PWA:** Screen Wake Lock (screen only, Baseline 2025) — use in the office/transcript view so a phone on a desk stays on; it cannot keep the *host* awake.
- **UI/UX recommendation:** setting "Keep computer awake while sessions run" (default **off**, per-device), with modes *while agents run* / *always* / *schedule*, a status chip showing backend (`caffeinate`, `systemd-inhibit`, `SetThreadExecutionState`) and "awake since", plus a warning that lid-close/manual sleep still wins on Windows and `-s` needs AC power on macOS.

|---|---|---|
| Apple notarization cost ($99/yr) and process | certain / medium | Budget it; use App Store Connect API key in CI; unsigned builds only for local dev. |

## 4. Rejected options (with reasons)

- **Electron 44** — size/memory, 8-week major churn, no advantage unless WebKitGTK fails; ToDesktop SaaS $100–1,200/mo.
- **Electrobun 2** — single maintainer (explicit no-PR-review policy), Win arm64 beta w/o JIT, missing notifications/Linux menus (Mar 2026), docs drift; runtime now "Cottontail" ◐.
- **Wails v3** (Go), **Dioxus** (Rust), **Neutralino** (C++ core, thin ecosystem), **Pake** (GPL wrapper), **Capacitor Electron** (unmaintained).
- **Ink** as *primary* TUI — Node/React-centric; fine fallback if OpenTUI's Bun coupling is a problem.
- **oclif** / **@effect/cli** — framework weight vs single-binary goals (Effect only if the core adopts Effect).
- **node-notifier, play-sound, omelette, @pnpm/tabtab, update-notifier** — stale or npm-only; replace with direct OS calls / own code.
- **MessageFormat 2 / i18next-mf2** — no engine, ~10 downloads/week.
- **UnifiedPush** for iOS — Android/Linux only. **Expo Push** as the privacy-preserving channel — payload transits Expo.
- **Claude-Code-style vendor relay** — not reusable; architecture lessons only (outbound-only, QR pairing, short-lived scoped creds).

## 5. Open questions for the owner

1. **Signing entity:** Do you have (or want) a Czech company (s.r.o.) for Azure Artifact Signing organisation validation, or should Windows builds start unsigned/OV-signed? Budget for Apple's $99/yr?
2. **Runtime commitment:** Bun-only core (enables OpenTUI, `bun build --compile`) vs keeping Node 26 compatibility (SEA, broader hosting)?

6. **Mobile scope:** Is a PWA (push only when installed on iOS) acceptable for v1, or is a store app (Expo/Capacitor, $99 + $25 + EAS) required?

8. **Translation workflow:** Tolgee vs Weblate Libre vs plain JSON in-repo + LLM pre-translation; who reviews Czech?
9. **Keep-awake semantics:** "while any session runs" vs manual toggle vs schedule; should it also prevent *display* sleep (burn-in on OLED) by default?
