## 0. Read first: blockers, surprises, corrections

- **Daily releases.** The Agent SDK ships a new version almost every weekday ("parity with Claude Code v2.1.x"); 0.3.289 was published 2026-10-03T20:12Z `[N1]`. Pin the newest version at least a day old at install time (0.3.288 of 2026-10-02 as of this sheet) and let Renovate move it under the cooldown.
- **Peers of the Agent SDK** `[D1]`: `@anthropic-ai/sdk >=0.93.0`, `@modelcontextprotocol/sdk ^1.29.0`, `zod ^4.0.0`. The lockfile already holds one `zod@4.6.5`, which satisfies both the Agent SDK (`^4`) and the ACP SDK (`^3.25 || ^4`); the other two peers are absent and become dependencies of `plugins/agent-claude` (Bun installs peers through the dependant). Optional dependencies carry the bundled Claude Code binary per platform (`@anthropic-ai/claude-agent-sdk-{linux-x64,linux-arm64,linux-x64-musl,linux-arm64-musl,darwin-x64,darwin-arm64}`); the spec's "the user's installed `claude`, the bundled binary only when none is installed" maps to `pathToClaudeCodeExecutable` ("Uses the built-in executable if not specified") `[D2]`.
- **Engines.** The Agent SDK declares `node >=18.0.0` `[D1]`; `@anthropic-ai/claude-code` 2.1.289 declares `node >=22.0.0` `[N2]`. The SDK's `executable: 'bun' | 'deno' | 'node'` ("JavaScript runtime to use for executing Claude Code. Auto-detected if not specified") and `executableArgs` choose the runtime of the CLI child `[D2]`; the docs mention `bun build --compile` support through an `extractFromBunfs()` helper (SDK ≥ 0.3.144) `[A1]` — the compiled ByteBureau binary must prefer the installed `claude`; probe in the plan's first task.
- **`permissionMode` changed in 0.3.286** `[A2]`: omitting it leaves the mode to Claude Code's defaults; pass `'default'` explicitly for manual approvals. Values: `default | acceptEdits | bypassPermissions | plan | dontAsk | auto` `[D3]`. The spec's mapping (`supervised` → `default` with brokered prompts; `autonomous` → `auto`; `yolo` refused in SP1) holds.
- **No `authStatus()` method.** The spec's §8.1 names one; the SDK has none `[D4]`. Auth state arrives as the `auth_status` message (`{ type: 'auth_status', isAuthenticating, output: string[], error?, uuid, session_id }`) and the init message's `apiKeySource` says where the credential came from (`'ANTHROPIC_API_KEY' | 'apiKeyHelper' | '/login managed key' | 'none'` — `none` for a claude.ai OAuth login) `[D5]`; `accountInfo()` returns `{ email?, organization?, subscriptionType?, tokenSource?, apiKeySource?, apiProvider? }` `[A1][D4]`. The plan amends the spec: the profile check runs `accountInfo()` under the profile environment and maps an `auth_status` error to `loggedOut`/`expired`.
- **`Settings.attribution` became `boolean | {...}` in 0.3.281** (breaking for code that read `attribution.commit`) `[A2]`.
- **ACP.** `@agentclientprotocol/sdk` 1.7.0 (2026-10-02) `[N3]`; protocol v1 is stable (`PROTOCOL_VERSION = 1` in `dist/schema`), v2 is a draft under the `./experimental/v2` export (`PROTOCOL_VERSION = 2`, "may change incompatibly in any SDK release") `[C1][C2]`. Peer dependency `zod ^3.25.0 || ^4.0.0`, no `engines` field `[C2]`. The old `@zed-industries/agent-client-protocol` (0.4.5, 2025-10) is dead `[N4]`.
- **codex-acp moved**: `@zed-industries/codex-acp` (0.16.0; the repository was archived on 2026-07-22) → `@agentclientprotocol/codex-acp` 2.1.1 (2026-10-02), binary `codex-acp` `[V1][N5]`. The spec's preset command changes accordingly.
- **Gemini CLI's flag is `--acp`** (`--experimental-acp` in older third-party docs); `loadSession` is supported; 0.62.0 (2026-10-03), `node >= 20` `[V2][N6]`.
- **OpenCode**: `opencode acp` (ACP v1 over stdio, nd-JSON); `opencode-ai` 1.18.34 (2026-10-03) `[V3][N7]`.
- **pi-acp** 0.0.34 (2026-09-24, MIT; `engines.node >= 20`, the README asks for Node 22+ and `pi` ≥ 0.81.0): spawns `pi --mode rpc`, keeps a session map in `~/.pi/pi-acp/session-map.json` for `session/load`, reports context usage as ACP `usage_update`; "MVP-style", "expect some minor breaking changes" `[V4][N8]`.
- **Secrets.** `Bun.secrets` exists since Bun 1.2.21 (2025-08) `[B1][B2]`: `get/set/delete({ service, name[, value, persist] })`, backends Keychain Services (macOS), libsecret (Linux: a secret-service daemon must run), Windows Credential Manager; value size "typically 2048–4096 bytes", service and name under 256 characters. Probe `[P1]`: macOS 15, Bun 1.4.2 — `set`, then `get` returned the value, `delete` returned `true`, a second `get` returned `null`; no Keychain prompt appeared for an item the same `bun` binary created. Tests run under Node (Vitest), so the kernel's `SecretStore` port gets a `Bun.secrets` implementation for the daemon and a file-backed one (0600, under the home) for tests and for headless Linux without a secret service.

## 1. Claude Agent SDK (TypeScript) — the surface §8.1 needs

- `query({ prompt: string | AsyncIterable<SDKUserMessage>, options })` → `Query extends AsyncGenerator<SDKMessage, void>`; streaming input mode is an async-iterable prompt; `Query.streamInput(stream)` exists as well `[A1]`.
- `Options` `[A1][D2]`: `settingSources: ('user' | 'project' | 'local')[]`; `canUseTool(toolName, input, { signal, suggestions?, blockedPath?, mcpServer?, decisionReason?, defaultToNo?, suppressAlwaysAllowRule?, toolUseID, agentID?, requestId }) => Promise<PermissionResult | null>` with `PermissionResult = { behavior: 'allow', updatedInput?, updatedPermissions?, toolUseID? } | { behavior: 'deny', message, interrupt?, toolUseID? }`; `hooks: Partial<Record<HookEvent, HookCallbackMatcher[]>>` with `HookEvent` ∈ {`PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PostToolBatch`, `Notification`, `UserPromptSubmit`, `UserPromptExpansion`, `SessionStart`, `SessionEnd`, `Stop`, `StopFailure`, `SubagentStart`, `SubagentStop`, `PreCompact`, `PostCompact`, `PreModelSwitch`, `PostModelSwitch`, `PermissionRequest`, `PermissionDenied`, `Setup`, `TeammateIdle`, `TaskCreated`, `TaskCompleted`, `Elicitation`, `ElicitationResult`, `ConfigChange`, `WorktreeCreate`, `WorktreeRemove`, `InstructionsLoaded`, `CwdChanged`, `FileChanged`, `DirectoryAdded`, `MessageDisplay`}; `resume: string`, `continue: boolean`, `forkSession: boolean`; `includePartialMessages`; `env: Record<string, string | undefined>` (replaces the child's environment when set — §13's allowlist applies here); `cwd`; `pathToClaudeCodeExecutable`; `executable`, `executableArgs`; `permissionMode`; `maxTurns`; `systemPrompt: string | string[] | { type: 'custom', prompt, snapshot? } | { type: 'preset', preset: 'claude_code', append?, excludeDynamicSections?, snapshot? }`; `allowedTools`/`disallowedTools`; `model`; `effort: 'low' | 'medium' | 'high' | 'xhigh' | 'max'`; `thinking: { type: 'adaptive' } | { type: 'enabled', budgetTokens } | { type: 'disabled' }` (`maxThinkingTokens` deprecated); `mcpServers`; `abortController`; `verbatimPrompts` (0.3.280).
- `Query` methods `[A1]`: `interrupt()`, `setPermissionMode()`, `setModel()`, `getContextUsage({ detail })`, `accountInfo()`, `supportedModels()`, `supportedCommands()`, `mcpServerStatus()`, `rewindFiles()`, `initializationResult()`, `reinitialize()`, `streamInput()`, `close()`, plus plugin, skill and MCP controls.
- Messages the adapter maps `[D3][D5]`: `system/init` (`apiKeySource`, `claude_code_version`, `cwd`, `tools`, `mcp_servers[{ name, status, source? }]`, `model`, `permissionMode`, `slash_commands`, `agents?`, `betas?`) → `session.ready`; `assistant` (`message: BetaMessage`, `context_usage?: SDKContextUsage { model, total_tokens, … }`, `error?`) and `stream_event` (partial, with `includePartialMessages`) → message and tool events, ephemeral deltas; `result` success (`duration_ms`, `duration_api_ms`, `is_error`, `num_turns`, `result`, `stop_reason`, `total_cost_usd` — cumulative across the turns of a streaming-input session, read the latest; `usage: NonNullableUsage` — the main loop only, per turn; `modelUsage: Record<string, ModelUsage { inputTokens, outputTokens, thinkingTokens?, cacheReadInputTokens, cacheCreationInputTokens, webSearchRequests, costUSD, contextWindow, maxOutputTokens, … }>` — "the correct field for token/cost accounting", cumulative; `permission_denials: { tool_name, tool_use_id, tool_input }[]`; `queued_turn_count?`) and `result` error (`subtype: 'error_during_execution' | 'error_max_turns' | 'error_max_budget_usd' | 'error_max_structured_output_retries'`) → `turn.completed` with `usage_json`, or the turn errored; `rate_limit_event { rate_limit_info: { status: 'allowed' | 'allowed_warning' | 'rejected', resetsAt?, rateLimitType?: 'five_hour' | 'seven_day' | 'seven_day_opus' | 'seven_day_sonnet' | 'seven_day_overage_included' | 'overage', utilization?, overageStatus?, isUsingOverage?, surpassedThreshold? } }` ("for claude.ai subscription users") → `ratelimit.updated`, and `session.paused` with `resets_at` when `rejected`; `system/compact_boundary { compact_metadata: { trigger: 'manual' | 'auto', pre_tokens, post_tokens?, duration_ms? } }` → `compaction.completed`; `system/api_retry { attempt, max_retries, retry_delay_ms, error_status, error }` → `session.warning`; `system/session_state_changed { state: 'idle' | 'running' | 'requires_action' }` (`requires_action` while an MCP elicitation waits, 0.3.280); `auth_status` → the provider's auth state.
- Permission brokering: `canUseTool` is invoked only when the permission flow falls through to a prompt `[A1]`; `AskUserQuestion` arrives as a tool call — the exact shape through `canUseTool`/`PreToolUse` is probed in the plan's first task.

## 2. ACP v1 (`@agentclientprotocol/sdk` 1.7.0) — the surface §8.2 needs

- Client side `[C2][C3]`: `client({ name })` → `ClientApp` with typed handlers, or `new ClientSideConnection(toAgent, stream)` (the older form); `ndJsonStream(output, input)` wraps the child's stdio.
- Agent methods a client calls (`AGENT_METHODS`, v1) `[C2]`: `initialize`, `authenticate`, `providers/list|set|disable`, `session/new`, `session/load`, `session/set_mode`, `session/set_config_option`, `session/prompt`, `session/cancel` (notification), `mcp/message`, `session/list`, `session/delete`, `session/fork`, `session/resume`, `session/close`, `logout`, `nes/*`.
- Client methods an agent calls (`CLIENT_METHODS`, v1) `[C2]`: `session/request_permission`, `session/update` (notification), `fs/write_text_file`, `fs/read_text_file`, `terminal/create|output|release|wait_for_exit|kill`, `mcp/message`, `elicitation/create|complete`, `$/cancel_request`.
- Requests `[C1]`: `session/new { cwd, mcpServers, additionalDirectories? }` → `{ sessionId, configOptions?, modes? }`; `session/prompt { sessionId, prompt: ContentBlock[] }` → `{ stopReason }`; `session/request_permission { sessionId, toolCall, options[] }` → `{ outcome }` with option kinds `allow_once | allow_always | reject_once | reject_always` and a `cancelled` outcome; `terminal/create { sessionId, command, args?, cwd?, env?, outputByteLimit? }` → `{ terminalId }`; `terminal/output` → `{ output, truncated, exitStatus? }`.
- Capabilities `[C1]`: client `{ fs: { readTextFile, writeTextFile }, terminal: boolean, auth?, elicitation?, session? }`; agent `{ loadSession, promptCapabilities: { image, audio, embeddedContext }, mcpCapabilities: { http, sse }, sessionCapabilities: { close, delete, list, resume }, auth }`.
- Session update kinds (v1 schema) `[C2]`: `user_message_chunk`, `agent_message_chunk`, `agent_thought_chunk`, `tool_call`, `tool_call_update`, `plan`, `plan_update`, `plan_removed`, `available_commands_update`, `current_mode_update`, `config_option_update`, `session_info_update`. `_meta` is reserved for extensions ("implementations MUST NOT make assumptions about values at these keys") `[C1]` — the spec's `bytebureau.usage`/`bytebureau.rateLimit` extension convention is allowed.
- Agents `[V1]–[V4]`: Codex — `codex-acp` (`@agentclientprotocol/codex-acp`), auth by `OPENAI_API_KEY`/`CODEX_API_KEY` or the ChatGPT login of the Codex CLI (`CODEX_HOME` for the profile directory — unverified); Gemini — `gemini --acp` (`loadSession` yes; `unstable_setSessionModel`; auth and config directory are not in the ACP document — `GEMINI_API_KEY`, `~/.gemini` unverified); OpenCode — `opencode acp` (ACP v1; credentials location and `opencode auth login` unverified); pi — `pi-acp` (spawns `pi --mode rpc`; sessions in `~/.pi/agent/sessions`, map in `~/.pi/pi-acp/session-map.json`; `usage_update` with context usage).

## 3. Secrets

- `Bun.secrets.get({ service, name }) → Promise<string | null>`, `.set({ service, name, value, persist?: 'local' | 'enterprise' }) → Promise<void>` (replaces an existing entry), `.delete({ service, name }) → Promise<boolean>`; asynchronous on Bun's thread pool `[B1]`. Probe `[P1]` as in §0.
- `@napi-rs/keyring` 2.1.0 (Rust `keyring` bindings) is the Node fallback if ever needed `[N9]`; `cross-keychain` builds on it. For Phase C the `SecretStore` port gets a `Bun.secrets` implementation in the daemon and a file-backed implementation under the home for tests and headless Linux; the CLI never prints a secret.

## Recommendations for the plan

- Pin `@anthropic-ai/claude-agent-sdk` to the newest version at least a day old at the first install, with Renovate on the daily releases under the cooldown; add `@anthropic-ai/sdk` and `@modelcontextprotocol/sdk` as dependencies of `plugins/agent-claude` (peers).
- Pass `permissionMode: 'default'` explicitly for `supervised`; `'auto'` for `autonomous`; keep `yolo` refused.
- Amend §8.1: `authStatus()` → `accountInfo()` plus the `auth_status` message and `apiKeySource` of `system/init`; `getContextUsage()` after each turn; `modelUsage` as the accounting source and `total_cost_usd` as the running total.
- Amend §8.2's presets: `codex-acp` from `@agentclientprotocol/codex-acp`; `gemini --acp`; `opencode acp`; `pi-acp`.
- `SecretStore`: `Bun.secrets` in the daemon, a file store for tests and headless Linux; probe `Bun.secrets` inside the compiled binary in the first task.
