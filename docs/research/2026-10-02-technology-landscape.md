## 1. Hard constraints discovered (these shape the design more than any library choice)

### 1.1 Anthropic subscription policy (pillar "zero extra cost")
Primary sources: Claude Code legal page, support article 15036540 (updated 2026-06-16), Agent SDK overview, authentication and headless docs.

- OAuth/subscription login is "designed to support ordinary use of Claude Code and other native Anthropic applications". An end user **may sign in to the unmodified Claude Code binary with their own subscription, including where a platform hosts Claude Code**.
- Third-party developers **may not** offer claude.ai login in their own product, route requests through Free/Pro/Max credentials on behalf of their users, or **collect, store or intermediate claude.ai credentials or session tokens**. The Agent SDK overview adds: "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK."
- Current usage rule (support article): the planned monthly "Agent SDK credit" was **paused on 2026-06-15**; "nothing has changed: Claude Agent SDK, `claude -p`, and third-party app usage still draw from your subscription's usage limits". The policy flipped four times in 2026 (Jan 9 block → Feb 20 "not permitted" → Apr 5 cut-off → May 13 reinstatement → Jun 15 pause) — treat it as volatile.
- `claude setup-token` (1-year `CLAUDE_CODE_OAUTH_TOKEN`) is officially for "CI pipelines, scripts, or other environments" with a Pro/Max/Team/Enterprise plan. `--bare` mode never reads subscription OAuth (API key only) and "will become the default for `-p` in a future release".
- Consumer terms forbid account sharing and "automated or non-human means" except via API key or explicit permission; the AUP forbids multi-account circumvention.
- Branding: a product must not be called "Claude Code"; allowed: "Claude Agent", "{Name} Powered by Claude".

**Consequences for ByteBureau**
1. ByteBureau orchestrates the **user's own, user-installed, unmodified `claude` binary** (headless `-p --output-format stream-json`, or the Agent SDK which spawns the same binary) under the login the user performed themselves. ByteBureau never reads, copies, stores or proxies OAuth tokens. In containers the user logs in once into a per-workspace `CLAUDE_CONFIG_DIR` volume (paste-code flow) or supplies a `setup-token` as their own secret.
2. API-key mode (and Bedrock/Vertex/Foundry) is a first-class alternative, not an afterthought; it is the only path Anthropic endorses for "developers building products".
3. **Automatic multi-account token rotation is out** (it is exactly "intermediating credentials" plus account pooling). What is in: named profiles (`CLAUDE_CONFIG_DIR` / `CODEX_HOME`) the user logs into individually, manual profile switching, usage pacing (pause at e.g. 80 % of the 5-hour window) and a usage HUD fed only by sanctioned sources (SDK `accountInfo()`, `SDKRateLimitEvent`, status-line `rate_limits`), never the undocumented `/api/oauth/usage` endpoint.
4. OpenAI is friendlier: "Sign in with ChatGPT" (launched 2026-09-29) explicitly admits **open-source tools** to a user's Plus/Pro plan with per-app weekly caps (listed OSS partners: OpenClaw, OpenCode, Pi, T3); device-code login exists; ChatGPT-managed auth in CI is documented as an "advanced option". ByteBureau should apply for a client ID.

### 1.2 Anthropic Remote Control is not zero-knowledge
"All traffic travels through the Anthropic API over TLS"; "the session transcript … is stored on Anthropic servers"; subscription-only; unavailable through gateways/proxies and for Zero-Data-Retention organisations. Codex Remote relays through OpenAI servers with no E2EE statement. This is the opening for ByteBureau's blind relay, but E2EE phone control itself is not unique (Paseo, Happy already do it with TweetNaCl over a blind relay).

### 1.3 Name collision
`github.com/ByteBureau` is a Belgian organisation (created 2023-02-21), `github.com/byte-bureau` a user (2026-07-15), `bytebureau.com` parked since 2017 (expires 2026-12-05), and a 2020 "ByteBureau" company deck exists; a Belgian software house of that name is a live EU trademark-opposition risk. Free today: npm `bytebureau` / `@bytebureau/*`, crates, PyPI, Docker Hub, Homebrew, `.dev/.app/.ai/.org/.net/.cz`, GitHub orgs `getbytebureau`, `bytebureauhq`, `bytebureau-dev`, `bytebureau-app`. Run TMview/BOIP/ÚPV clearance before investing in branding.

### 1.4 Asset licences
LimeZu "Modern Interiors/Office" forbids redistribution (committing it to a public repo is a risk, not a precedent). Mana Seed forbids use "alongside AI-generated code". LPC is CC-BY-SA and 64 px. Safe: Kenney (CC0) for prototyping; original art generated with PixelLab (you own outputs, commercial OK) / Retro Diffusion and cleaned in Aseprite, published CC0/CC-BY.

### 1.5 Hardware & browser realities
- Anthropic's own sizing for a Claude Code session is ~4 GiB RAM + 2–4 CPU → Raspberry Pi 5 runs 1 session (8 GB) or 2–3 (16 GB); Docker Sandboxes (`sbx`) is not available on Pi OS.
- WebGPU: Chrome 113+, Safari iOS 26+, macOS 26 partial, Firefox disabled → the office renders on **WebGL2** with WebGPU as an optional path. 120 Hz: Chrome uncapped; WKWebView uncapped only on macOS 26.
- Floating-point determinism: `Math.sin/cos/tan/exp/log/pow…` differ between V8 and JavaScriptCore (measured) → the simulation uses integer cell math and bans transcendental functions.
- Code signing: Apple notarisation needs the $99 programme; Azure Artifact Signing's individual validation is US/Canada-only → a Czech s.r.o./OV certificate or SmartScreen prompts on Windows.

## 3. Per-area synthesis (facts that drove the choices)

### 3.1 Agent harnesses & providers (reports 01, 02, 02b)
- Claude Code 2.1.287 (2026-10-01). ### 3.2 Sandboxing (report 04 + Anthropic sandbox docs)
- Docker Sandboxes (`sbx`): microVM per agent with its own kernel and Docker daemon, host-side credential proxy (VM sees sentinel values), deny-by-default network; free standalone CLI (macOS 14+ Apple Silicon, Windows 11, Ubuntu 24.04+KVM); proprietary; the `docker sandbox` Desktop plugin was removed in Desktop 4.93 (2026-09-28) → isolate behind the driver.
- Anthropic's sandbox taxonomy: sandboxed Bash tool (OS primitives, no native Windows) → sandbox runtime (whole process incl. MCP/hooks) → dev container (official example with default-deny iptables; supports `--dangerously-skip-permissions`, which refuses to run as root) → custom container → VM → cloud sessions. Claude Code needs `enableWeakerNestedSandbox` in unprivileged containers; `docker` CLI is incompatible with its inner sandbox.
- Credential strategy inside containers: user `/login` into a per-workspace `CLAUDE_CONFIG_DIR` volume; or `CLAUDE_CODE_OAUTH_TOKEN` as the user's own secret; or API key injected by a host egress proxy (`ANTHROPIC_BASE_URL`); Codex `codex login --device-auth` into `CODEX_HOME`; git push tokens minted per session by the core; Jira/Slack credentials never enter the container.
